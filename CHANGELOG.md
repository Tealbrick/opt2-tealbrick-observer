# Changelog

All notable changes to Observer. One section per released version (handbook §3.2).

## Unreleased (0.1.0)
- Scaffold from create-tealbrick-miniapp (template ci-v9.10); pins miniapp-sdk 0.1.25, manifest 0.1.18, conformance 0.1.18, ui 0.2.4. Refs: C160, C169, C190
- S1 core: one handler per manifest op (28) on the `obs_*` tables: agent `status` (labels and counts only), `job_pause`, `flag` (delivered records only, 50 a day); owner sources, jobs (state machine), rules (locked rule 0), review decisions (secret records: drop only; outbox rows pending), records, deliveries, privacy, purge. Connect-dependent ops answer `connect_unavailable` until Connect offers `data_pull`. Manifest invariant tests, conformance fixtures. Refs: C169
- S1 review fixes: one outbox row per (record, revision, destination) and a new decision overwrites a non-sent row; narrowing and purge also clear deliveries, records and thread subjects; JS-normalised exclusions (`author_key`); `flag` only on delivered records, one open flag per agent and record, new `review_decide` decision `keep`; secrets refused in `review_decide` and `delivery_retry`; `status` shows `liveJobId`/`historyJobId`, `job_pause` answers one `not_found`; allow-list guards for agent output and pinned companions; damaged exclusions fail closed; HMAC message digests; `warning` kept on the delivery row. Refs: C169
- S1 second review: superseded deliveries cannot be revived (every decision clears unsent rows; retry matches the last decision via `decided_destination`), flag raises the revision, `text_gone` and `delivery_held` guards, all decision guards inside `decideRecord` with a fail-closed secret check, digest key states with attention (`digest_key_unavailable`, `digest_key_lost`) and rule 0 created first, exclusions normalised on write, a full new exclude replaces a damaged one, narrowing nulls the record thread. Refs: C169
- ui 0.3.0 (kit art and colour for Observer); THIRD_PARTY_NOTICES versions and the ui kit licence corrected (C220). Refs: C190, C220
- S3 classify and route: pure detectors (secrets, email, phone, IBAN mod 97, card Luhn + issuer, government ids SK/CZ/DE/US, address, special-category words EN/SK/DE), redaction with overlap merge, ingest helper that replaces secrets before storage, windowing, actionable scorer, router (rule 0 first) and `applyRouting`; `review_get` returns detected spans (offsets and classes only). A 16 KiB message classifies in about 1 ms. Refs: C169
- S3 review fixes: secret detection for identifier keys (DB_PASSWORD, aws_secret_access_key, "access_token"), any 4+ character value after `:` / `=`, many more key formats, entropy fallback, joined-text scan, normalised matching (NFKC, zero-width, look-alikes); card windows, phone lists and bare numbers, SK/CZ account numbers, all-SEPA IBAN table, SSN keyword form, Slovak addresses, diacritic-free and hyphenated special-category words; every class except the secret is PII for the router; rule word validation; marker defanging; thread and author cleaning; persisted window → record mapping with clamped times; edits re-classify their record; email `+tag` / dot-insensitive senders. Refs: C169
- S3 review 2: the joined secret scan also runs after an edit or a late message (three separators, every seam, 256 KiB cap), a secret record stores no new text; many more formats (PuTTY, bare AWS secret, DigitalOcean, Twilio, Mailgun, Shopify, Linear, Sentry, PyPI, RubyGems, Google, Azure AD, Discord, base64-wrapped PEM, decoded base64); key names with noise, plurals, SQL, CLI flags, escaped JSON, YAML blocks, SK/CZ/DE words; keyword matching on a copy without marks / controls with small-capital, look-alike and digit-for-letter folding; new class `suspect_secret` (random-looking tokens) that is never delivered automatically; bounded patterns and overlapping 64 K windows. Refs: C169
- S3 review 3: the suspect_secret check has no whole-URL exemption (userinfo, path segments, query, fragment, webhook paths), flags hex of 32+ characters without a hash word, UUID keys next to key words, 2-class and letter-only tokens, base32 seeds, 16–20 character tokens with 12+ different characters, and tokens written in groups; it also runs on the joined text and the seams, and on thread subjects and author handles; held deliveries of a record that went back to Review are marked superseded and `deliverySendable` is the check S4 must call. Refs: C169
- S5 owner UI: Sources (cards, live and history jobs, add-source StepFlow, history start, honest state while Connect gives no data access), Review (marked spans, redacted preview, possible secret held until the owner says they read the text, recognised secret drop-only, deliver / deliver redacted / keep / drop), Routing (rule 0 locked, add / edit / move / delete), Activity (held, failed and superseded deliveries, retry), Privacy (retention, delete now), Settings (Connect and Knowledge required); `sources_available` and `rules_list` also return `targets`, the apps the slice lets Observer call, so a destination Observer cannot reach is greyed. Product copy: Observer "removes the secrets it recognises and holds possible secrets for your review", never "all secrets". happy-dom tests per page. Refs: C169
- S5 review fixes: a record with a suspect_secret hit blanks its thread subject, message thread and author handle in every answer (`recordView`, `recordDetail`); `review_decide` takes `acknowledged` and refuses deliver as is of such a record without `acknowledged: true` (`acknowledgement_required`, 400); the UI opens suspect text redacted ("Show the original text"), enables the tick only while the original is shown, says "held as a whole" when no span marks it, disables Deliver while Knowledge is missing, says that delivery starts in a later version, and says "Observer cannot read sources yet" without a Portal hint. Refs: C169
- S5 re-check fixes: `classifyMeta` also looks at subject and handle on the normalised and look-alike-folded copies (full-width, zero-width, mixed script); records not yet routed (`open`, `classified`) show no subject or author; `review_decide` takes `revision` and answers 409 `revision_changed` when a newer one exists (the UI refreshes the record, takes the tick back and says so); a message of a possible secret with no marked span is redacted as a whole, per message. Refs: C169
- S2 ingest: Connect companion (`data_accounts_list`, `data_catalog`, `data_pull`, crud `["read"]`, DESIGN §4.5; the guard requires it and fires on any extra op); the real Connect port over `ctx.callApp`; messages/1 vendored from spec-v0.1.42 (byte copy, PROVENANCE, sha test), every pulled row checked, a row that does not conform skipped and counted (`counts.skipped`); jobs `obs.live` and `obs.backfill` on the SDK runner: anchor captured before the job, one page = one transaction (messages + cursor + counts), then windows → records → classify → route; slice and owner pause read before every pull; `retryAfterS` honoured exactly; backoff with jitter (cap 15 min); 5 failures or a permanent refusal (caller_unverified, not_found, scope_denied, cursor_invalid) → `failed` + attention `jobs_failed`; Try again after `cursor_invalid` reads from Connect's start; 100 pulls a minute (25 kept for live); a history read stops at `maxMessages`.
