# Changelog

All notable changes to Observer. One section per released version (handbook §3.2).

## 0.2.0 (2026-10-27; C373 second brain)
**Observer reads sources and delivers to Knowledge** (C373 second brain). Refs: C169, C230, C322(6), C373
- S2 ingest (from the unfinished branch `wip/obs-s2-round3`, finished): Connect companion (`data_accounts_list`, `data_catalog`, `data_pull`, crud `["read"]`); the Connect port over `ctx.callApp`; messages/1 checked per row; ingest jobs `obs.live` / `obs.backfill` on the SDK runner (anchor first, one page = one transaction, cursor stored, `retryAfterS` honoured, backoff, 5 failures → failed + attention); a read Connect holds waits for Try again (no automatic recheck); history reads of what Connect kept.
- Documents sources (contract documents/1, spec main `0bd02e9`, reserved 0.1.83, vendored byte copy): `source_add` takes `dataset: "documents"` and collections; one record per document (text cleaned of control, bidi and zero-width characters, chunked under the 16 KiB message cap, one record); dedupe on (account, collection, id) (one collection per source, `rev` equality, `updatedAt` order, later row wins on a tie); a new revision retires the old record; `deleted: true` follows privacy `onSourceDelete`; rule 0, excluded authors and PII review work as for messages (a document may have no author). `backfill_start` answers `history_not_needed` for documents; `backfill_estimate` counts documents. Migrations 0003-0005.
- S4 deliveries to Knowledge: outbox drain job `obs.deliver`: approved and rule-delivered records → `document_create` (rule area, else the owner's pick, else Knowledge's shared company area from `areas_list`) or `document_update` when the source revision changes (the Knowledge document id is kept per (account, collection, id)); idempotency key and exact call bytes replayed on retry; tags `observer`, `source:<collection>`, `pii:<class>`, `kind:<kind>` (`kind:table` for database table pages); `deliver_redacted` sends labels; CSV formula cells escaped; sent → record delivered; held → asked again every minute with the same key; refusals fail at once with a plain sentence, other errors back off and fail after 5; Knowledge missing → waits without an attempt; Task Board and Inbox rows fail with a sentence (not sent in this version).
- New person ops `delivery_target_get` / `delivery_target_set` (the Knowledge area); Routing shows the delivery target and counts; Sources show the dataset, last pull and counts, and add a documents source (account → Documents → collections); Activity shows Observer's own sentence for a waiting or failed delivery.
- QA-OBS11 fixes (migration 0004): the documents dataset is read as the state scan Connect makes it (cursor kept only mid-scan, a new scan from the start every interval, never faster than 5 minutes, default 15; never filtered by collection: Connect tombstones a deleted document only on a full scan, rows of other collections are dropped locally); a deletion is a tombstone and the Knowledge copy is archived (purge) or tagged `source-deleted` (keep); title, path, link and collection are classified and redacted (personal data only there goes to Review; the summary, title and tags never carry unredacted personal data; the link loses query, fragment and userinfo); the stored call (`payload_json`) is emptied when sent and when its record is purged, retired or narrowed, and a retry past the retention sends nothing; rows that come with `retryAfterS` are stored first; the document writer fails the page on any error that is not a row refusal; a stuck cursor stops the job after 3 pages with a visible sentence; delivered documents are tagged `untrusted`; `document_update` sends `expectedVersion` and leaves a human edit alone (the document is frozen: the delivery fails with a plain sentence on Activity, later revisions keep that one row, Retry makes a new document); a delivery that failed for good keeps no stored call and Retry builds it again from the record (text gone: it fails again at once with a plain sentence); archiving replaces the current Knowledge text only (Knowledge keeps its revision history); an unanswered `document_create` is settled before a newer revision updates the document.
- miniapp-sdk 0.1.40, manifest 0.1.31, conformance 0.1.30 (released tarballs; Observer has no scopes, so no acceptOffer UI).

## 0.1.1 (2026-10-26)
**Observer still cannot read sources.** It needs Connect's shared read access (`data_*` ops, R3), which Connect does not offer yet; on any workspace, also PROD, `source_add` and the backfill ops answer `connect_unavailable` (409) and no delivery is sent (S4). This release makes the detectors and the pages ready for that day.
- New detector `name` (person names, EN / SK / CZ / DE; medium to low confidence, deterministic, no model): a known given name and the capitalised words after it, any capitalised word after a courtesy title (Mr, pán, Frau) or a greeting (Dear, Ahoj, Liebe), and a short line after a sign-off (Thanks, S pozdravom, Viele Grüße). Given names that are also common words (Will, May, Frank) need a surname or a cue. Words inside email addresses and URLs are left to the email detector. Given-name lists: `src/detect/names-data.ts` (provenance in its header). A name is personal data: the record waits in Review unless a rule delivers it redacted (`[name]`). Routing rules can ask for it. Refs: C169
- Review says "Observer found no personal data (it checks …)" only when every detector, names included, found nothing. Refs: C169
- The "not available" notice now gives the next step: for Knowledge, add it to the workspace and give it a licence in Portal (Core grants a companion only to a deployed and licensed app); for Connect, nothing to do until Connect offers data access. Refs: C169

- S1 core: one handler per manifest op (28) on the `obs_*` tables: agent `status` (labels and counts only), `job_pause`, `flag` (delivered records only, 50 a day); owner sources, jobs (state machine), rules (locked rule 0), review decisions (secret records: drop only; outbox rows pending), records, deliveries, privacy, purge. Connect-dependent ops answer `connect_unavailable` until Connect offers `data_pull`. Manifest invariant tests, conformance fixtures. Refs: C169
- S1 review fixes: one outbox row per (record, revision, destination) and a new decision overwrites a non-sent row; narrowing and purge also clear deliveries, records and thread subjects; JS-normalised exclusions (`author_key`); `flag` only on delivered records, one open flag per agent and record, new `review_decide` decision `keep`; secrets refused in `review_decide` and `delivery_retry`; `status` shows `liveJobId`/`historyJobId`, `job_pause` answers one `not_found`; allow-list guards for agent output and pinned companions; damaged exclusions fail closed; HMAC message digests; `warning` kept on the delivery row. Refs: C169
